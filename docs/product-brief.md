# 스토리로그 제품 브리프

> 기획 근거: 사용자가 제공한 [Notion 조사 문서](https://app.notion.com/p/24-3be61e401e2a80e9afaded934e1ab96c?source=copy_link) 전문과 현재 GitHub 구현을 통합해 정리했다. Notion 원문은 대화에 첨부된 텍스트를 기준으로 분석했다.

## 1. 제품 정의

스토리로그는 사용자의 텍스트·음성·사진·영상 기록을 실제 경험에 근거한 스토리 카드로 정리하고, 채널별 콘텐츠 초안과 게시 승인까지 연결하는 개인 브랜딩 워크플로우다.

핵심 가치는 “AI가 대신 그럴듯한 글을 써 주는 것”이 아니다. 기록의 시작 부담을 낮추고, 사용자가 이미 겪은 사건·관찰·감정·의견·교훈을 콘텐츠 자산으로 축적하는 것이 핵심이다. AI는 원본을 정리하고 각도를 제안하지만 새로운 사실을 만들지 않는다. 공개 여부와 최종 표현은 항상 사용자가 결정한다.

제품을 한 문장으로 표현하면 다음과 같다.

> 나의 하루를 말로 남기면, 나다운 콘텐츠가 된다.

## 2. 해결하려는 문제와 초기 고객

예비 크리에이터는 이야기할 경험이 없어서가 아니라, 무엇을 어떻게 기록하고 채널에 맞게 바꿔야 할지 몰라 시작하지 못한다. 기존 AI 글쓰기 도구는 빈 입력창과 범용 초안을 제공해 시작 부담을 충분히 줄이지 못하고, 사용자의 실제 경험과 생성 문장의 근거를 분리해 보여 주지 않는 경우가 많다. 그 결과 사용자는 “이 글이 정말 내 이야기인가”를 신뢰하기 어렵다.

첫 고객은 AI·테크 분야의 예비 크리에이터다. 일상적으로 새로운 도구, 프로젝트, 업무 방식을 경험하고 배운 점을 갖고 있지만 이를 꾸준한 콘텐츠로 만드는 데 어려움을 겪는 사람을 우선한다. 이후 학생·직장인, 라이프스타일·교육·스타트업 크리에이터로 확장한다. 브랜드 매칭은 콘텐츠와 성과 데이터가 충분히 쌓인 뒤의 B2B2C 단계다.

## 3. 핵심 사용자 흐름

제품은 자유롭게 행동하는 에이전트보다 상태가 명확한 워크플로우로 동작해야 한다.

`CAPTURED → TRANSCRIBED → NORMALIZED → STORY_MINED → ANGLE_SELECTED → DRAFTED → QUALITY_CHECKED → WAITING_FOR_APPROVAL → APPROVED → PUBLISHED → MEASURED`

대표 흐름은 다음과 같다.

1. 사용자가 질문 카드 중 하나를 선택하고 1분 분량의 텍스트나 음성을 남긴다.
2. 시스템은 원본을 보존한 채 사건·관찰·감정·의견·교훈을 스토리 카드로 구조화한다.
3. 사용자는 원본 근거와 함께 스토리 카드의 사실성, 공개 위험, “나다움”을 확인한다.
4. 이야기 각도와 대상 독자를 고르면 LinkedIn, X, Instagram 등 채널별 초안이 생성된다.
5. 사용자는 수정·승인·거절 중 하나를 선택한다. 승인 전 자동 게시는 없다.
6. 승인한 콘텐츠를 복사·다운로드하거나 연결된 채널에 게시하고 기본 성과를 확인한다.

스토리 카드는 Draft보다 먼저 존재하는 핵심 객체다. 원본 구간, 사건, 관찰, 감정, 의견, 교훈, 민감도, 출처를 포함하며 이후 모든 초안은 어떤 스토리 카드와 원본에서 나왔는지 추적할 수 있어야 한다.

## 4. MVP 범위

현재 구현은 가장 작은 신뢰 검증 단위인 `텍스트 기록 → 스토리 카드 → 채널 초안 → 승인`을 실제 동작하도록 만든 수직형 MVP다. 사용자는 빈 프롬프트 대신 네 개의 질문 카드로 시작하고, 사건·예상 밖의 점·교훈을 입력한다. API는 입력된 사실만 재구성해 스토리 카드와 최대 3개 채널 초안을 반환한다. 화면은 비공개 원본, 공개 후보, 승인된 자산을 서로 다른 상태로 표시한다.

다음 MVP 확장에는 음성 녹음·업로드와 전사, 원본/전사 교정, 사진·영상 근거 연결, 브랜드 프로필, 승인 콘텐츠 메모리, 초안 직접 편집, 삭제·내보내기, 한 개 채널의 실제 게시, 게시 이력과 기본 성과가 포함된다.

초기 범위에서 제외할 항목은 실시간 전화, 음성 복제, 완전 자동 게시, DM 자동화, 광고주 자동 매칭, 고급 분석, 팀 워크스페이스다. 이 기능들은 핵심 신뢰 가설 검증 전에 복잡도와 위험을 크게 높인다.

## 5. 신뢰·안전 원칙

- 원본, 전사, 스토리 카드, 채널 초안을 별도 데이터로 저장한다.
- 원본 근거와 AI가 재구성한 표현을 시각적으로 구분한다.
- 기록별 공개 범위와 보관 기간을 선택할 수 있게 한다.
- 개인정보와 민감 정보를 탐지해 게시 전 경고한다.
- 플랫폼 토큰은 암호화하고 사용자별 데이터 접근을 격리한다.
- 승인·수정·게시 이력을 감사 로그로 남긴다.
- 사실이 아닌 표현, 공개 위험, “나답지 않음” 피드백을 다음 초안에 반영한다.

## 6. 성공 지표

북극성 지표는 `주간 활성 사용자당 승인 콘텐츠 수`다. 단순 생성량보다 사용자가 자기 이야기라고 믿고 승인한 결과를 측정한다.

초기 검증 목표는 첫 기록 완료율 60% 이상, 첫 초안 도달 시간 5분 이내, 초안 승인율 40% 이상, 사실 오류로 인한 거절률 5% 이하, 7일 내 두 번째 기록률 30% 이상, 승인 콘텐츠의 복사·다운로드·게시율 50% 이상이다.

반드시 검증할 가설은 세 가지다. 첫째, 사용자가 실제로 하루를 기록하는가. 둘째, AI가 찾은 스토리를 사용자가 “내 이야기”라고 평가하는가. 셋째, 사용자가 그 결과를 믿고 승인·게시하는가.

## 7. 수익화와 단계별 로드맵

제품 수익은 개인 구독으로 시작한다. 무료 플랜에는 월 기록 수, 음성 분량, 생성 채널 수를 제한하고 유료 플랜에는 더 긴 기록, 승인 콘텐츠 메모리, 예약 게시, 내보내기를 제공한다. 초기에는 소규모 유료 파일럿으로 기록 지속성과 승인율을 검증한다. 브랜드 매칭과 거래 수수료는 충분한 콘텐츠·성과 데이터가 쌓인 이후에 검토한다.

사용자의 수익화는 승인한 실제 경험 콘텐츠를 자산으로 쌓는 것부터 시작한다. 대표 콘텐츠가 만들어지면 UGC 제작, 실제 사용 제품의 추천·제휴, 브랜드 협업 제안 순으로 작은 매출을 검증한다. 팔로워 수보다 특정 독자에게 유용한 관점과 일관된 증거를 먼저 만든다.

제품 개발 순서는 다음과 같다.

- Phase 0: 예비 크리에이터 인터뷰와 기록 행동 검증
- Phase 1: 텍스트·음성 기록에서 신뢰할 수 있는 스토리 카드 생성
- Phase 2: 이야기 각도 선택과 채널별 초안, 승인 피드백
- Phase 3: 실제 게시, 이력, 기본 성과 수집
- Phase 4: 반복 사용 최적화, 구독, 제한적인 B2B2C 실험

현재 저장소는 Phase 1의 텍스트 흐름과 Phase 2의 초기 승인 경험을 구현한다. 다음 개발 우선순위는 음성 전사보다 먼저 데이터 저장과 상태 전이를 영속화하는 것이며, 그 다음 음성 기록과 실제 게시 연결을 추가한다.
