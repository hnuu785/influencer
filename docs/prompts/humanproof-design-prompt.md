당신은 12년 이상의 경력을 가진 시니어 프로덕트 디자이너이자 프론트엔드 엔지니어다. 단순한 AI SaaS 템플릿이 아니라, 실제 디자인 스튜디오가 사용자 조사와 브랜드 전략을 거쳐 제작한 것처럼 정교한 모바일 우선 반응형 웹앱을 구현하라.

프로젝트명은 **HumanProof**이며, 핵심 메시지는 다음과 같다.

> “당신의 하루에는 이미 콘텐츠가 있습니다.”

HumanProof는 사용자의 일기, 메모, AI 대화, 음성, 사진, 영상을 수집하여 개인의 경험·생각·감정·배움을 Story Card로 정리하고, 이를 Instagram, Reels, X, LinkedIn 등의 콘텐츠로 변환하는 퍼스널 브랜딩 서비스다.

단순한 AI 글 생성 서비스가 아니다. 사용자의 실제 경험을 근거로 콘텐츠를 만들고, 생성된 문장이 어떤 기록에서 나왔는지 확인할 수 있어야 한다. 사용자는 결과를 수정·승인·거절하며, 서비스는 이 과정을 통해 사용자의 말투와 선호를 학습한다.

## 구현 환경

- 기존 `influence-fe` 프로젝트 구조와 설정을 먼저 확인하고 이를 유지한다.
- Next.js App Router와 TypeScript를 사용한다.
- 기존 백엔드와 인프라는 수정하지 않는다.
- 모바일 우선으로 구현하되 태블릿과 데스크톱까지 자연스럽게 확장한다.
- 환경변수의 API 주소를 통해 백엔드와 연결할 수 있는 구조로 만든다.
- API 키와 인증 비밀정보는 절대 프론트엔드에 포함하지 않는다.
- 실제 API가 준비되지 않은 화면은 현실적인 fixture 데이터로 구성한다.
- 구현 후 lint와 production build를 실행하고 오류를 수정한다.

## 디자인 방향

브랜드 인상은 다음 다섯 단어로 정의한다.

- Human
- Authentic
- Editorial
- Calm
- Trustworthy

AI SaaS에서 흔히 보이는 보라색 그라데이션, 네온 컬러, 과도한 글래스모피즘, 우주·로봇 일러스트, 의미 없는 대시보드 카드, 지나치게 둥근 버튼을 사용하지 않는다.

프리미엄 저널 앱과 현대적인 에디토리얼 매거진이 결합된 인상을 만든다. 사용자의 기록과 이야기가 시각적 중심이 되어야 하며, AI는 전면에 드러나지 않고 조용히 사용자를 돕는 역할로 표현한다.

### 컬러 시스템

다음 컬러를 기반으로 접근성을 만족하는 디자인 토큰을 구성한다.

- Primary background: 따뜻한 아이보리 `#F7F5F0`
- Primary surface: 화이트 `#FFFFFF`
- Primary text: 잉크 블랙 `#171717`
- Secondary text: 웜 그레이 `#6F6B65`
- Border: `#E6E1D9`
- Brand accent: 딥 포레스트 `#245C4F`
- Evidence accent: 뮤트 블루 `#376FA3`
- Recording accent: 소프트 코랄 `#D9695F`
- Success: 차분한 그린
- Warning: 탁한 앰버

순수한 검정·흰색 대비만 반복하지 말고 따뜻한 배경색과 표면 차이를 활용한다. 그림자는 넓고 옅게 사용하고, 테두리는 꼭 필요한 곳에만 적용한다.

### 타이포그래피

- 한글 본문은 Pretendard Variable 또는 동일한 수준의 가독성 좋은 산세리프를 사용한다.
- Story Card의 핵심 문장이나 인용문에는 절제된 세리프 서체를 보조적으로 사용할 수 있다.
- 제목은 크기만 키우지 말고 자간, 행간, 굵기 차이로 명확한 위계를 만든다.
- 본문 최소 크기는 모바일 기준 15~16px로 유지한다.
- 긴 한글 문장이 어색하게 잘리거나 버튼 밖으로 넘치지 않게 한다.
- 실제 서비스에서 사용할 수 있는 자연스러운 한국어 문구를 작성하고 Lorem Ipsum은 사용하지 않는다.

## 레이아웃 원칙

- 4px 기반의 일관된 간격 시스템을 사용한다.
- 모바일 좌우 여백은 20px를 기본으로 한다.
- 카드 모서리는 16~24px 범위에서 기능에 따라 구분한다.
- 한 화면에는 하나의 핵심 행동만 강하게 강조한다.
- 모든 콘텐츠를 동일한 카드 안에 넣지 말고 여백, 배경, 타이포그래피로 영역을 구분한다.
- 터치 영역은 최소 44px 이상으로 만든다.
- 모바일에서는 하단 내비게이션을 사용한다.
- 데스크톱에서는 왼쪽 사이드바, 중앙 콘텐츠, 선택적인 오른쪽 근거 패널 구조로 전환한다.
- 중앙 콘텐츠의 최대 폭은 약 680~760px로 제한해 모바일 화면이 단순히 늘어난 것처럼 보이지 않게 한다.

반응형 기준은 최소 다음 화면에서 검증한다.

- 360px
- 390px
- 430px
- 768px
- 1024px
- 1440px

## 핵심 사용자 흐름

다음 흐름이 한 번에 이해되도록 설계한다.

기록하기 → Story Card 추출 → 실제 기록 근거 확인 → 수정·승인 → 채널 선택 → 콘텐츠 생성 → 최종 편집 → 게시 또는 다운로드

## 필요한 화면

### 1. 온보딩

3단계 이내로 구성한다.

1. 사용자의 전문 분야와 관심사를 선택한다.
2. 주요 독자와 사용할 SNS 채널을 선택한다.
3. 원하는 말투와 브랜딩 목표를 선택한다.

예시 선택값:

- AI·개발
- 데이터 분석
- 창업
- 커리어
- 일상
- 담백하고 전문적인 말투
- 솔직하고 인간적인 말투
- 경험을 중심으로 설명하는 말투

온보딩 마지막에는 “완벽한 콘텐츠보다, 오늘의 한 문장부터 시작해보세요.”라는 메시지와 시작 버튼을 배치한다.

### 2. 홈

홈의 최상단에는 일반적인 대시보드 통계가 아니라 사용자의 기록을 유도하는 질문을 배치한다.

> “오늘 어떤 순간이 가장 나다웠나요?”

그 아래에 다음 기록 방식을 제공한다.

- 텍스트 작성
- 음성으로 말하기
- 사진 추가
- 영상 추가

중앙의 음성 기록 버튼은 시각적으로 중요하지만 과도하게 크거나 화려하지 않게 만든다.

홈에는 다음 정보도 자연스럽게 배치한다.

- 오늘의 기록 여부
- 최근 생성된 Story Card
- 연속 기록 일수
- 이번 주 발견된 주요 주제
- 아직 콘텐츠로 만들지 않은 경험

숫자 중심의 분석 화면보다 기록을 시작하게 만드는 감정적인 흐름을 우선한다.

### 3. 기록 화면

기록 작성 화면은 빈 문서처럼 편안하고 집중할 수 있게 만든다.

- 텍스트 입력
- 음성 녹음과 파형
- 사진·영상 첨부
- 기록 시각
- 공개 범위
- 관련 프로젝트 또는 주제 선택
- 저장 버튼

음성 녹음 중에는 녹음 시간, 일시정지, 종료가 명확하게 보여야 한다. 사진과 영상은 작은 파일 입력창이 아니라 실제 편집 앱처럼 썸네일 스트립으로 보여준다.

### 4. Story Card 생성 상태

“AI가 분석 중입니다” 같은 추상적인 문구만 보여주지 않는다.

다음 단계를 순차적으로 표현한다.

- 경험에서 중요한 순간 찾는 중
- 생각과 감정 정리 중
- 과거 기록과 연결하는 중
- 콘텐츠 소재로 구성하는 중

짧은 문구와 세련된 skeleton UI를 사용한다. 과장된 로딩 애니메이션은 피한다.

### 5. Story Card 상세

이 화면이 서비스의 핵심 화면이다.

Story Card에는 다음 정보가 포함된다.

- 경험을 압축한 제목
- 한 문장 핵심 이야기
- 실제 상황
- 당시 생각과 감정
- 새롭게 알게 된 점
- 콘텐츠로 사용할 관점
- 관련 주제 태그
- 연결된 과거 경험
- 생성 근거 개수
- 수정·승인·거절 버튼

예시 데이터는 다음 맥락으로 작성한다.

“오늘 해커톤에서 문제를 정의하고 사용자의 행동을 고민하는 과정이 예상보다 즐거웠다. 시작하기 전에는 막힐까 두려웠지만, 실제로는 문제를 함께 정의하는 과정에서 가장 많은 에너지를 얻었다.”

Story Card를 단순한 정보 카드가 아니라 사용자의 하루를 보존하는 작은 에디토리얼 문서처럼 디자인한다.

### 6. 근거 확인 패널

생성된 문장을 선택하면 해당 문장의 근거가 된 원본 기록을 확인할 수 있어야 한다.

- 원본 텍스트 구간
- 음성 녹음 시간
- 사진 또는 영상 썸네일
- 기록 날짜
- 관련 과거 경험

근거가 있는 문장은 뮤트 블루 표시를 사용한다. 사용자가 “이 문장은 내 실제 기록에서 나왔다”는 사실을 즉시 이해할 수 있게 한다.

모바일에서는 bottom sheet, 데스크톱에서는 오른쪽 패널로 표시한다.

### 7. 승인 및 피드백

Story Card 하단에는 다음 행동을 명확하게 제공한다.

- 내 이야기와 잘 맞아요
- 일부 수정할게요
- 내 이야기와 달라요

거절 시 긴 설문을 요구하지 말고 다음과 같은 빠른 이유를 선택하게 한다.

- 말투가 나와 다름
- 사실과 다른 내용이 있음
- 중요한 내용이 빠짐
- 너무 과장됨
- 공개하고 싶지 않은 내용

사용자의 수정 전·후 차이가 이후 개인화에 사용된다는 점을 부담스럽지 않은 문구로 안내한다.

### 8. 콘텐츠 변환

승인된 Story Card를 어떤 채널의 콘텐츠로 만들지 선택한다.

- Instagram Caption
- Instagram Carousel
- Reels Script
- X Thread
- LinkedIn Post
- YouTube Shorts Script

채널을 선택하면 단순 텍스트가 아니라 실제 채널 구조와 유사한 미리보기를 제공한다.

Instagram Carousel의 경우:

- Cover
- Hook
- Situation
- Insight
- Takeaway
- CTA

Reels Script의 경우:

- 0~3초 Hook
- 본문
- 장면 제안
- 자막
- 마무리 CTA

### 9. 콘텐츠 편집

편집 화면은 생성 결과와 미리보기를 동시에 확인할 수 있게 만든다.

기능:

- 문장 직접 수정
- 길이 조절
- 말투 조절
- Hook 다시 만들기
- CTA 변경
- 해시태그 제안
- 원본 근거 보기
- 복사
- 다운로드
- 승인

데스크톱은 편집기와 미리보기의 2열 구조, 모바일은 탭 또는 segmented control 구조를 사용한다.

“다시 생성”을 가장 강한 버튼으로 만들지 않는다. 사용자가 결과를 소유하고 직접 편집하는 경험이 중심이 되어야 한다.

### 10. Story Library

과거 경험과 Story Card를 검색하고 다시 사용할 수 있는 공간이다.

- 날짜별 탐색
- 주제별 필터
- 원본 유형별 필터
- 승인 상태
- 사용된 채널
- 콘텐츠 제작 여부
- 자연어 검색

검색 예시:

- “내가 개발하면서 가장 힘들었던 순간”
- “AI 프로젝트에서 배운 점”
- “아직 Instagram에 올리지 않은 경험”

리스트는 반복되는 동일 카드 그리드 대신 날짜 그룹과 에디토리얼 타임라인을 조합한다.

### 11. Experience Graph

사용자의 반복되는 경험과 전문성을 시각적으로 보여준다.

예시:

- AI Development 92
- Data Analysis 84
- Product Thinking 76
- Cloud 67
- Collaboration 61

레이더 차트 남용을 피하고, 막대·연결 관계·대표 Story Card를 함께 보여준다. 각 분야를 선택하면 해당 점수가 만들어진 실제 경험을 확인할 수 있게 한다.

### 12. Creator Value 및 향후 브랜드 기회

해커톤 데모에서는 실제 광고 기능을 만들지 않고 미래 확장성을 보여주는 미리보기 화면으로 구성한다.

예시:

- AI Coding Tool — 94% Match
- Cloud Service — 87% Match
- Data Platform — 81% Match

선택 시 다음 정보를 보여준다.

- Experience Match
- Audience Match
- Content Fit
- 추천 이유
- 예상 광고 단가 범위
- 관련 경험
- 관련 콘텐츠

이 영역은 현재 기능과 혼동되지 않도록 “Coming next” 또는 “Preview” 상태로 표시한다.

## 내비게이션

모바일 하단 내비게이션:

- 오늘
- 기록
- 스토리
- 인사이트
- 내 정보

기록 버튼은 중앙에 독립적인 주요 행동으로 배치할 수 있다. 아이콘에는 Lucide 스타일의 일관된 선형 아이콘을 사용하고 이모지를 내비게이션 아이콘으로 사용하지 않는다.

데스크톱에서는 동일한 메뉴를 왼쪽 사이드바로 전환한다.

## 상태 디자인

모든 핵심 화면에 다음 상태를 구현한다.

- 최초 사용 empty state
- 데이터 로딩 skeleton
- API 오류
- 네트워크 오류
- 업로드 진행 상태
- 생성 실패 후 재시도
- 검색 결과 없음
- 기록은 있지만 승인된 Story Card가 없는 상태
- 콘텐츠 생성 전 상태

오류 메시지는 기술 용어 대신 사용자가 다음 행동을 알 수 있는 문장으로 작성한다.

## 인터랙션

- 전환 애니메이션은 150~240ms 범위에서 절제되게 사용한다.
- 버튼과 카드에는 작은 hover·pressed·focus 반응을 제공한다.
- Story Card 승인 시 과도한 축하 효과 대신 색상과 위치 변화로 완료감을 준다.
- bottom sheet와 modal은 자연스러운 이동과 명확한 닫기 동작을 제공한다.
- `prefers-reduced-motion`을 지원한다.
- 키보드 탐색과 명확한 focus ring을 제공한다.
- 색상만으로 상태를 구분하지 않는다.

## 디자인 완성도 기준

- 한눈에 기능의 우선순위가 보여야 한다.
- 모바일에서 한 손으로 주요 기능을 사용할 수 있어야 한다.
- 실제 데이터가 들어가도 레이아웃이 깨지지 않아야 한다.
- 콘텐츠 길이가 달라도 카드 높이와 정보 위계가 안정적이어야 한다.
- 문구, 아이콘, 여백, 정렬이 모두 같은 디자인 시스템 안에서 작동해야 한다.
- 같은 형태의 카드와 버튼을 반복 배치하는 방식으로 화면을 채우지 않는다.
- 시각적으로 화려한 것보다 사용자의 실제 기록과 이야기가 돋보이게 한다.
- 생성형 AI가 만든 흔한 랜딩 페이지처럼 보이지 않게 한다.
- 실제 디자이너가 서비스의 철학, 사용자의 감정, 장기적인 사용 흐름을 고민한 흔적이 보여야 한다.

## 최종 구현 요구사항

1. 기존 코드를 먼저 분석한다.
2. 필요한 화면과 공통 컴포넌트 구조를 설계한다.
3. 디자인 토큰과 반응형 레이아웃을 먼저 정의한다.
4. 모바일 화면부터 구현한다.
5. 태블릿과 데스크톱 레이아웃을 별도로 다듬는다.
6. 실제 한국어 fixture 데이터를 넣는다.
7. 주요 입력·승인·편집·검색 인터랙션이 작동하게 한다.
8. 접근성, 빈 상태, 오류 상태를 구현한다.
9. 모든 주요 해상도에서 오버플로와 잘림을 확인한다.
10. lint와 production build가 성공하도록 마무리한다.

설명용 정적 시안이나 랜딩 페이지만 만들지 말고, 사용자가 기록을 입력하고 Story Card를 검토하고 콘텐츠로 변환하는 핵심 흐름을 실제로 체험할 수 있는 프로덕션 수준의 반응형 웹앱으로 구현하라.
