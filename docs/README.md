# Influence 제품 문서

이 디렉터리는 Influence 팀이 제품·디자인·개발 결정을 내릴 때 사용하는 제품 기준 문서다.

## 서비스 한 줄 정의

**스토리로그(가칭)는 사용자가 일상을 텍스트·음성·사진·영상으로 남기면, 그 경험을 나다운 퍼스널 브랜딩 콘텐츠로 기획·제작·승인·게시할 수 있게 돕는 AI 워크플로우 서비스다.**

AI가 사용자를 대신해 허구의 콘텐츠를 만드는 것이 아니라, 사용자의 실제 경험에서 소재를 찾고 관점과 말투를 보존한 채 채널별 제작안으로 발전시키는 것이 핵심이다.

## 핵심 제품 파이프라인

```text
사용자 기록
→ StoryCard
→ 레퍼런스 훅·포맷 검색
→ Content Brief
→ 채널별 Storyboard
→ Reel·Carousel·Story 및 텍스트 초안 제작
→ 품질·원본성 검사
→ 사용자 승인
→ Trial Reel 또는 게시
→ 성과 학습
```

세 가지 산출물은 다음과 같이 구분한다.

| 산출물 | 답하는 질문 | 역할 |
|---|---|---|
| `StoryCard` | 어떤 경험을 콘텐츠로 만들 것인가? | 원문에서 사건·관찰·감정·의견·배움을 추출하고 근거와 연결한다. |
| `Content Brief` | 누구에게, 왜, 무엇을 전달할 것인가? | 독자·목적·핵심 메시지·훅 방향·포맷을 결정한다. |
| `Storyboard` | 실제로 어떻게 보여줄 것인가? | 장면·슬라이드·자막·시간·시각 자료·CTA를 제작 가능한 수준으로 설계한다. |

## 문서 지도

- [제품 기획 기준](./product-spec.md): 문제 정의, 사용자, 핵심 개념, AI/RAG 워크플로우, Instagram 제작 전략, 데이터 모델, 품질 기준, MVP 범위, 지표와 로드맵

## 제품 원칙

1. 실제 경험이 모든 콘텐츠의 출발점이다.
2. 원문에 없는 사실·성과·감정을 만들지 않는다.
3. 외부 레퍼런스는 패턴을 학습하기 위한 자료이며 문장·장면을 복제하지 않는다.
4. 사용자의 관점·말투·금지 주제·수정 이력을 개인 브랜드 메모리로 축적한다.
5. 공개 게시 전에는 항상 사용자가 근거와 결과물을 검토하고 승인한다.
6. 참여율만 높이는 자극성보다 개인성·사실성·유용성·브랜드 신뢰를 우선한다.
7. 워크플로우 상태와 권한은 애플리케이션이 소유하고, LLM은 구조화·추천·변환에 한정한다.

## 문서와 구현 상태의 구분

`product-spec.md`는 목표 제품 정의다. 문서에 적힌 기능이 현재 코드에 모두 구현되었다는 의미는 아니다.

2026-08-16 기준 저장소에는 반응형 UX 프로토타입과 FastAPI·PostgreSQL·Redis 실행 기반이 있다. 실제 사용자 데이터 저장, pgvector 기반 RAG, LLM 호출, 음성·미디어 처리, 인증, 게시 API와 성과 수집은 후속 구현 범위다.
